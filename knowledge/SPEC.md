# notes knowledge-instance contract

This `notes` repository is one personal kgdistiller instance. It owns personal inputs,
reviewed identity decisions, durable private graph state, an adopted static
site export, and the note/Typst build that consumes selected export artifacts.
It does not own or render a public graph frontend. It also does not own the
kgdistiller engine, product Skills, agents, workflow implementation, or tests.

## Authorities

- `sources.json` defines personal source taxonomy, bounded paths, publish/listed
  policy, fields, topics, and canonical web routes.
- `workflow-policy.json` classifies local non-authorities and frozen legacy
  backlog.
- `alignments.json` stores reviewed personal identity mappings.
- `graph/` is durable private graph state. Its agent-authored entries, evidence,
  and semantic edges are personal decisions; never discard them by rebuilding
  from note markers alone.
- `notes/` contains the authored Markdown, Typst, and LaTeX source material.

Candidates, reviews, temporary receipts, and other disposable local build
artifacts belong under the ignored `knowledge/build/` directory. There is no
local runtime/search index. These files are not authorities.

## Adopted site export

`export/site/` is a complete static bundle generated by a selected kgdistiller
product commit:

```text
knowledge/export/site/
├── manifest.json
├── graph.json
├── knowledge-registry.typ
└── verify_export.py
```

The manifest uses `kgdistiller-static-export-v1` and binds the producer repository,
version and full commit, source repository revision and digest, private graph
digest, public graph digest, counts, and every artifact's byte length and
SHA-256. `graph.json` is already hydrated and privacy-filtered to sources with
`publish: true`; its taxonomy is limited to ancestors reachable from those
sources, and all edges/references are filtered consistently. The Typst registry
uses the same public node set.

The committed bundle is an adoption record, not a live dependency. Updating the
kgdistiller development checkout does not change the site. Adoption happens
only when an explicit, verified atomic replacement advances the bundle and its
recorded product commit; a failed replacement preserves the prior bundle. The
export is produced only from a clean, committed notes repository, so
`source.revision` names the exact source/registry/private-graph input commit.
The resulting bundle is committed in a following commit.

## Build boundary

The homepage repository `qiulinfan/qiulinfan.github.io` reads this repository
as its `notes` dock and publishes it. Its development, tests, and GitHub Pages
builds, like this repository's own checks, must work with no kgdistiller
product checkout, no submodule, and no installed kgdistiller package. They verify the committed bundle and render it; they never
refresh the private graph or generate public artifacts.

Private source hashes are checked during explicit authoring/adoption. Public
site code must never expose the private source inventory or unlisted graph
content. It publishes no graph page or graph JSON endpoint; the verified
`graph.json` stays an internal adoption/build record.
